# 图生皮肤的新路径：从规范化渲染到 Minecraft UV 重建

**作者：EntropyDrop Dev Team**
**日期：2026-07-25**


## 前言

在上一篇文章《[从参考图到 Minecraft 皮肤：生成模型训练实践](/public/blog/skingen)》中，我们介绍了一条以图生图模型为核心的技术路线：先把参考图转换为包含 UV 贴图和多视角渲染图的复合目标图像，再通过后处理提取 64×64 皮肤。这条路线证明了大模型能够学习角色特征、像素风格与 Minecraft 皮肤之间的映射，但也遇到了明显的瓶颈。

模型往往只学到了视觉上的近似关系，并没有真正理解衣服上的火箭、小熊、文字或徽章等图形。面对这些细节，它更容易把高分辨率图案直接缩小，得到类似普通降采样的结果：细节逐渐消失，颜色相互混合，关键轮廓的边缘也变得模糊。真正理想的低像素表达，应当先理解图形的含义和最具辨识度的结构，再在有限的像素空间中重新组织这些信息，而不是简单地压缩原图。

为了暂时跨过这个瓶颈，并继续验证后续的 UV 还原方案，我们很不情愿地引入了闭源图像模型作为辅助，将图生皮肤拆分为两个阶段：第一阶段把任意角色图片转换为结构固定的 Minecraft 前后渲染图；第二阶段再从渲染图中逆向还原皮肤 UV 贴图。闭源模型并不是我们希望长期依赖的最终方案。现阶段的重要目标之一，是持续收集经过筛选和验证的“原始角色图—规范化渲染图—UV 皮肤”数据，以便进一步训练一个完全不依赖闭源模型的图生皮肤模型。

## 相关工作与方案演进

据我们目前能够追溯到的公开资料，这条思路较早由网友 DDJ 提出。2025 年底，他演示了使用 Banana 图像模型辅助生成 Minecraft 皮肤的方法；2026 年 2 月，又在此基础上训练了专用模型，以改进从生成图中提取 UV 贴图的效果，并随后公开了模型。相关资料包括：

- [2025 年 11 月 23 日发布的方案演示](https://www.bilibili.com/video/BV1NqUNBVEu5)
- [2026 年 2 月 16 日发布的 UV 提取改进](https://www.bilibili.com/video/BV1muZTBkE53)
- [开源模型 MCSkin](https://huggingface.co/d1ngdongji/MCSkin)

2026 年 3 月，另一组研究者提出了相近的两阶段路线，并在论文 [BLOCK: An Open-Source Bi-Stage MLLM Character-to-Skin Pipeline for Minecraft](https://arxiv.org/abs/2603.03964) 中进行了更系统的研究。

在这些工作的基础上，我们主要沿两个方向继续改进：

1. 提高 Banana 模型输出的稳定性，减少相机视角、人物姿态、缩放比例和画面位置的偏差，使内层与外层皮肤尽可能落在预定的投影网格中。
2. 重新设计 UV 还原流程，从规范化渲染图中直接重建带透明通道的 64×64 UV 贴图。

## 零、前置基础：可微渲染器与训练管线

在进入分阶段的技术细节之前，需要先介绍贯穿整个第二阶段的核心基础设施——可微 Minecraft 渲染器（Differentiable Minecraft Renderer）。它是 SkingToolkit 能够以"几何优先"方式工作的关键依赖，负责生成预计算的 UV 投影映射和训练标签。

### 0.1 项目关系

`differentiable_minecraft_renderer` 是一个独立于 SkingToolkit 的项目，与 `mc_skin_utils`（Minecraft 皮肤网格处理库）共同构成 SkingToolkit 的底层依赖。

### 0.2 可微渲染器的两项核心职责

**职责一：生成预计算 UV 投影映射**

渲染器通过 `generate_mappings.py` 离线预计算每种视图配置下的像素级 UV 映射，保存为 `mappings_{W}x{H}/` 目录下的 `.pt` 文件。

生成方法利用了颜色编码反查：对每个 64×64 UV texel 赋予唯一的高对比度 RGB 颜色（通过 `code = ((idx * 2053 + 1381) & 0x0FFF)` 将 4096 个 texel 映射到 12 位色彩空间的互异值），渲染为 64×64 的"调色板皮肤"。用 `mc_skin_utils` 以指定相机参数渲染该调色板皮肤后，再从输出图像中解码每个像素的颜色，反查其来源 UV texel。这种方法比解析 Minecraft 模型的三角形面片和 UV 坐标更可靠——它天然处理了遮挡关系、深度排序和内外层的 alpha 合成结果。

对每个视图配置，渲染器生成以下映射数据：

| 映射张量 | 形状 | 内容 |
| :--- | :--- | :--- |
| `inner_uv_map` | H×W×2 | 内层皮肤各屏幕像素对应的 UV 坐标（0–63），无覆盖处为 (-1,-1) |
| `inner_mask` | H×W | 内层覆盖的二值掩码 |
| `outer_uv_map` | H×W×2 | 外层皮肤各屏幕像素对应的 UV 坐标 |
| `outer_mask` | H×W | 外层覆盖的二值掩码 |
| `outer_uv_layers` | L×H×W×2 | 外层渲染经过深度排序后的逐层 UV 坐标 |
| `outer_masks` | L×H×W | 对应逐层掩码 |
| `composite_uv_layers` | L×H×W×2 | 内外层合成的深度排序 UV，含 `composite_is_decor_layers` 标注每层是否为外层 |
| `geometry_uv_layers` | 72×H×W×2 | Steve 模型全部 72 个矩形面（6 部件 × 6 面 × 2 层）的深度排序 UV，以 `geometry_sort_indices` 按深度排列 |
| `geometry_masks` | 72×H×W | 对应逐面掩码 |

`SkingToolkit/renderer.py` 中的 `DifferentiableRenderer` 是这些映射的加载器与执行引擎。它不重新计算投影，而是加载 `.pt` 文件中预计算好的 grid 和 mask，通过 `F.grid_sample` 直接从皮肤图集采样像素，再按 alpha 合成规则叠层渲染。在 SkingToolkit 中，`DifferentiableRenderer` 同时服务于两个场景：

- **训练时**：对每张 GT 皮肤渲染所有配置视图，生成逐像素的路由标签（部件、表面、层级、UV 坐标）。在后续章节介绍的可微训练分支中，模型的软输出会被投射为临时 UV，再由渲染器重新渲染以计算多视图一致性损失。
- **推理时**：加载与训练一致的映射文件，为几何拟合提供查表数据（参见第三节），并生成诊断图中的网格叠加。

**职责二：生成训练标签**

对训练集中的每张 64×64 GT 皮肤，渲染器以完全确定性的方式输出每个屏幕像素的来源信息。因为渲染器精确知道每个像素是从哪个 UV texel 采样而来、该 texel 属于哪个部件和面、来自内层还是外层，这些信息可以直接作为后续路由模型的监督标签，不需要任何人工标注。

具体而言，对每个配置的视图，渲染器为每个像素产生以下标签：

| 标签 | 取值空间 | 含义 |
| :--- | :--- | :--- |
| `foreground` | {0, 1} | 是否为前景（角色）像素 |
| `part` | {0,…,5} | 身体部件：头、躯干、左臂、右臂、左腿、右腿 |
| `face` | {0,…,5} | 立方体表面方向：前、后、左、右、上、下 |
| `layer` | {0, 1} | 内层或外层 |
| `route_role` | {0, 1, 2} | 路由角色：直接可见内层、直接可见外层、次级/背向表面（透过外层透明孔洞所见） |
| `surface` | 0…N-1 | 精确表面槽位（含复合映射和 geometry fallback 面） |
| `uv` | [0,1]² | 归一化 UV 坐标 |

其中 `route_role=2`（次级表面）的情况在外层皮肤中很常见：帽子或外套的透明区域会让渲染器"穿透"外层，采样到更深处的内层表面或背向面。这些像素被单独标记并路由到精确的 `surface` 槽位，而非被丢弃或强制归入最近的内层表面。

### 0.3 渲染器为何不能直接逆向阶段一的图片

一个很自然的问题是：可微渲染器已经能精确地从 UV 贴图渲染出 2D 图像（`skin → render`），那是否可以直接用它"反向"阶段一的输出，将规范化前后视图还原为 UV 贴图（`render → skin`）？

答案是不能。问题出在路由歧义。

渲染器的预计算映射文件提供的是"可能"关系——对屏幕上的每个像素，它列出了所有潜在的来源：内层头部的正面、外层头部的正面、内层头部的背面等等。这些候选的 UV 坐标是确定的，但**选择哪一个候选**却无法仅凭几何决定。当一个像素同时落在内外层的重叠区域时，它可能来自三层不同的表面——直接可见的内层、覆盖在其上的半透明外层，或透过外层镂空看到的更深表面。从渲染结果来看它们完全可能是同一种颜色。

类比来说：映射文件是一张详尽的公交线路图，列出了从每个站台出发可以到达的所有目的地。但它不能告诉你某个乘客此刻应该坐哪条线路——因为同一站台同时停靠内层、外层和次级表面三条线路，而乘客的着装（像素颜色）又可能完全一致。

这就是贯穿本文后半部分的核心分工：

- **渲染器**（0.2 节、第三节）：提供几何映射——"像素可能来自哪里"；
- **Dense UV Parser**（第四节）：做语义路由——"像素实际来自哪里"。

两者缺一不可。渲染器让系统不需要从零开始猜测 UV 映射；parser 让系统能在多个几何候选之间做出有依据的选择。

### 0.4 视图配置

渲染器与第二阶段路由模型的视图体系基于 `differentiable_minecraft_renderer/config.py` 中的固定配置。当前生产使用的默认视图为：

```text
front_left                     ← 前视图，小幅度行走姿态，正交投影，内层+外层
back_left                      ← 后视图，同上
```

关键参数：正交投影（`ortho=True`）、zoom=0.23、look_at_y=16、行走姿态旋转角（手臂 ±10°、腿部 ∓10°）。这些参数在训练、验证和推理中保持一致。视图名称被编码为 checkpoint 元数据，推理时自动匹配对应的映射文件。

### 0.5 语义 backbone 与特征缓存

第二阶段路由模型的语义分支依赖 Google 的 SigLIP2（`google/siglip2-base-patch16-224`）作为冻结的视觉 backbone。SigLIP2 不参与训练，但其输出需要在训练前预先计算并缓存，以避免每个 batch 都重新跑一次完整的前向传播。

缓存系统（`cache_semantic_features.py`）对数据集中的每张皮肤先渲染前后视图，再通过 SigLIP2 提取两类特征：

- **全局特征**（pooled embedding）：每视图 768 维向量，供后续路由模型的全局语义融合模块使用（详见第四节 MultiViewSemanticFusion）；
- **空间特征**（spatial patch features）：每视图 768×14×8 的张量（对 256×512 视图经 ViT patchify 后裁剪到非 padding 区域），供空间语义融合模块使用（详见第四节 SpatialSemanticFusion）。

两类特征均以 FP16 精度写入 memory-mapped 文件（`.bin`），由索引文件（`.idx`）记录每个样本的偏移量。对 180,000 张皮肤的数据集，空间特征缓存约 58 GiB，全局特征缓存约 0.5 GiB。训练时仅当前 batch 的切片被读入显存，不需要将全量缓存加载到 RAM。缓存键由数据集路径、视图配置、模型 ID 和样本数量共同决定，变更任一参数需重建缓存。

### 0.6 训练数据集

第二阶段的路由模型训练需要标准的 64×64 RGBA 皮肤 PNG 文件。Slim/Alex 模型（手臂宽度 3 像素）在加载时通过 `alice_to_steve()` 归一化到 Steve 布局（手臂宽度 4 像素）。数据集仅要求皮肤本身——训练不需要成对的控制图像，因为所有标签由渲染器自动生成。

这与阶段一形成了鲜明的互补关系：阶段一（图生皮肤模型）需要成对的"写实照片—目标图像"数据，数据获取是主要瓶颈；而阶段二（SkingToolkit）的标签完全自动化，瓶颈在于模型的路由精度而非数据标注。

## 一、阶段一：把任意参考图变成规范化前后视图

第一阶段采用多图参考。图 1 是待转换的角色原图；图 2、图 3 和图 4 则使用不同皮肤，但保持完全相同的画布布局、相机方向、人物姿态和模型比例。多张模板并不是为了向模型提供更多角色内容，而是反复强调输出必须遵循的几何约束，并共同限定 Minecraft 的低像素视觉风格。这样可以降低模型照搬某一张模板外观的概率，同时减少视角漂移、比例变化和肢体错位。

Prompt 的设计也围绕这两个目标展开：首先锁定 Minecraft 双图层玩家模型及其贴图分辨率；其次锁定相机、姿态和画面布局；最后才要求模型在这些约束内还原角色特征。当前使用的 Prompt 修改自 DDJ 推荐的版本，具体如下：

```text
生成 [图 1] 中角色的 Minecraft 形象。

- 人物模型必须与 Minecraft 玩家模型相同，并采用包含内层和外层贴图的双图层结构，不能添加额外的几何元素。贴图分辨率不得高于 Minecraft 支持的分辨率，参考 [图 2]、[图 3] 和 [图 4]。

- 生成角色的尺寸、朝向、姿势、相机视角和画面位置必须与 [图 2]、[图 3] 和 [图 4] 完全一致。

- 使用容易区分前景的纯色背景。

- 在满足上述约束的前提下，尽可能准确地还原 [图 1] 中角色的外貌特征、全身服装和饰品，但不要生成手持物品或披风。
```

测试中我们发现，图像生成模型很难稳定遵循 Prompt 中的精确数值。直接指定 yaw、pitch、FOV 或角色像素尺寸，不仅不能保证几何一致，有时反而会增加输出波动。相比抽象的描述，模型更擅长从参考图中模仿相机方向、构图比例和人物姿态。因此，这一阶段的重点应当放在参考模板的设计上。

模板也并非越复杂越好，比如在模版中增加单独的内外层皮肤渲染或者增加网格辅助，Banana模型无法输出正确的图像。经过多轮测试，我们最终得到了一组稳定性较高的渲染模板，其共同特征如下：

- 使用正交投影，不添加光照，避免透视缩放和明暗变化干扰后续取色；
- 采用 1:1 正方形画布，左半部分放置角色正视图，右半部分放置角色后视图，并使用随机纯色背景；
- 角色采用小幅度摆动手脚的行走姿态，使四肢与躯干适当分离，同时避免姿态变化过大；
- 除各部件的底面外，绝大多数皮肤区域都能在前后视图中找到对应的可见颜色。

## 二、前景提取

由于阶段一利用模版和提示词引导，为角色生成了具有较高色差的纯净背景，我们可以采用一个简单的策略提取前景：读取图像左上角第一个像素作为背景种子，并通过泛洪算法移除与其连通、颜色差异位于容差范围内的区域。

尽管存在一些边缘情况使得背景出现在非联通区域，使得一些背景色混入前景，但通常这种错误在后续流程中会得到修正。如果未来有很强的准确性和通用性的需求，可以再专门训练一个分割模型。

泛洪得到的 mask 和透明 cutout 保留在原始输入坐标中。进入几何路由前，parser 预测的全局 affine 会把图像、密集 logits 和前景 mask 一起对齐到固定渲染器的 canonical 坐标。这里不能直接对二值 mask 使用最近邻采样：即使只有很小的缩放误差，单像素帽沿、发梢或后脑外层凸起也可能在重采样时整体消失。当前实现改为对 mask 做双线性覆盖率重采样，只要 canonical 像素与变换后的源 mask 覆盖率超过极低阈值就予以保留；背景色边缘检查、网格覆盖率和每外层 texel 至少 15 个有效源像素的门控仍负责排除被一并带入的无效边缘。

推理会同时保存两套诊断依据：

- `foreground_cutout.png` 与 `foreground_mask.png`：affine 前、原始输入坐标中的泛洪结果；
- `parser_debug_observed_canonical.png`：affine 后、路由前实际使用的前景 mask。

日志中的 `canonical_foreground_coverage_rescued_pixels` 表示相对于旧的最近邻采样，新方法保住了多少个边缘像素。这样可以把“前景提取本身漏掉了像素”和“正确的原始 mask 在几何对齐时被侵蚀”区分开。

## 三、几何拟合：预计算 UV 投影映射

前景分离后，系统不再对角色做任何形式的姿态估计或关键点检测，而是直接将已知的 Minecraft Steve 几何体通过固定相机参数投影到图像平面。这一步的核心数据结构是预计算的 UV 投影映射（precomputed UV mapping），由可微 Minecraft 渲染器离线生成并保存为 `.pt` 文件。

### 3.1 映射文件的生成与结构

渲染器使用与阶段一输出完全一致的相机配置——正交投影、固定视角、无光照、无透视缩放——对标准 Steve 模型（6 个身体部件 × 6 个立方体面 × 2 层 = 72 个矩形面）逐像素计算以下信息：

- **`inner_uv_map`** (H×W×2)：每个屏幕像素对应内层 64×64 UV 图集上的 (x, y) 浮点坐标。若该像素不落在任何内层表面上，值为 `(-1, -1)`。
- **`inner_mask`** (H×W)：二值掩码，标记该像素是否被内层几何体覆盖。
- **`outer_uv_map`** (H×W×2) 与 **`outer_mask`** (H×W)：对应的外层几何体投影，使用外层立方体（尺寸略大于内层，头部为 9/8 倍、躯干和四肢为 8.5/8 和 4.5/4 倍）计算。
- **深度排序的复合映射**：对于同时被内外层覆盖的像素，提供从相机出发的深度排序结果，使系统能够区分"直接可见的内层""直接可见的外层"和"透过外层透明孔洞看到的更深表面"。

在推理时，这些映射文件随第二阶段路由模型的 checkpoint 一同加载，每个视图（默认 `front_left` 和 `back_left`）各有一组映射。系统根据 checkpoint 记录的视图名称自动匹配对应的映射文件。

### 3.2 投影过程

对输入图像（前视图和/或后视图）的每一个像素，系统通过查表获得：

- **`body_part`**（uint8 值 0–5）：头部、躯干、右臂、左臂、右腿、左腿。由映射文件中该像素对应的 UV 坐标落在哪个部件的矩形区域决定。
- **`face`**（uint8 值 0–5）：前、后、左、右、上、下。在 UV 图集上，同一部件的六个面被分配在固定的矩形区域。
- **`layer`**（0 或 1）：内层或外层。由 `inner_mask` 和 `outer_mask` 联合判定。当像素同时被两层覆盖时，深度排序的复合映射给出最前表面的层级。
- **`uv`**（[0,1]² 归一化浮点坐标）：该像素在 64×64 UV 图集上的精确亚像素位置。对于外层像素，UV 坐标会自动偏移到外层在 UV 图集上的对应区域。
- **`secondary_surface_candidates`**：当外层像素被标记为透明时，该位置可能暴露出的更深表面列表（内层同一面或背向面）。

这一投影过程是纯查表操作——不涉及任何神经网络推理、可学习参数或迭代优化。输入图像分辨率固定为 256×512（左半 256×256 前视图 + 右半 256×256 后视图），映射文件的目标尺寸与之匹配。这直接约束了阶段一的输出规范：画布必须为 1:1 正方形，角色前后视图需分别占据左右半部分，相机、姿态和缩放需与映射文件的生成配置保持一致。

### 3.3 几何层的边界

几何拟合能够确定"每个像素可能来自哪些 UV texel"，但不能单独判断以下问题：

- 当前像素实际显示的是内层皮肤还是外层衣物——当两层在屏幕空间重叠时，仅有几何无法裁决层级归属；
- 同一颜色区域跨越多个人体部件的边界——例如脸部和颈部颜色相同时，颜色梯度无法提供分割线索，需要几何先验缩小候选部件范围，再由语义路由做最终判定；
- 被外层透明镂空暴露的内层像素，其精确 UV texel 可能来自多个候选表面——需要精确表面槽位分类来消除歧义。

这些恰好是下一节 Dense UV Parser 的职责。

## 四、Dense UV Parser：语义路由的模型架构与训练

几何层为每个屏幕像素提供了部件归属、表面方向和 UV 坐标候选，但无法可靠裁决一个关键问题：当前像素显示的是内层皮肤、外层衣物，还是透过外层透明区域看到的更深表面（次级表面）。Dense UV Parser 是一个经过监督训练的神经网络，专门解决这一路由决策。

### 4.1 网络架构

Parser 的主体是一个 U-Net 结构的全卷积网络（`DenseUVParserNet`），接受固定尺寸的 RGB 输入并输出逐像素的密集预测。具体结构如下：

**编码器—解码器主干**

| 层级 | 操作 | 输入通道 | 输出通道 | 空间尺寸（H×W） |
| :--- | :--- | :--- | :--- | :--- |
| 输入拼接 | view one-hot concat | 3 + V | 3 + V | 256×512 |
| stem | ConvBlock (3×3→3×3, GN+SiLU) | 3 + V | 32 | 256×512 |
| down1 | Conv2d (k4s2) + ConvBlock | 32 | 64 | 128×256 |
| down2 | Conv2d (k4s2) + ConvBlock | 64 | 128 | 64×128 |
| down3 | Conv2d (k4s2) + ConvBlock | 128 | 256 | 32×64 |
| mid | ConvBlock (3×3→3×3, GN+SiLU) | 256 | 256 | 32×64 |

其中 V 为视图类别数（默认 2，对应前视图和后视图）。每个视图被编码为一个 one-hot 向量，广播为与输入图像等高等宽的通道后与 RGB 拼接。这使得 parser 能够区分前视图和后视图中外观相同但空间含义不同的像素——例如纯色皮肤的前胸与后背在 RGB 上可能完全一致，但视图条件将它们映射到不同的 UV 区域。

**解码器（含跳跃连接）**

| 层级 | 操作 | 输入通道 | 跳跃连接 | 输出通道 | 空间尺寸 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| up2 | bilinear upsample + ConvBlock | 256 | s2 (128ch) | 128 | 64×128 |
| up1 | bilinear upsample + ConvBlock | 128 | s1 (64ch) | 64 | 128×256 |
| up0 | bilinear upsample + ConvBlock | 64 | s0 (32ch) | 32 | 256×512 |
| features | Conv2d (3×3) + SiLU | 32 | — | 32 | 256×512 |

所有采样层使用双线性插值（`align_corners=False`），跳跃连接将编码器对应层的特征图与上采样结果在通道维拼接后送入 ConvBlock。

**语义融合模块**

Parser 集成了两个可选的语义分支，均以冻结的 SigLIP2（`google/siglip2-base-patch16-224`）作为视觉 backbone：

1. **MultiViewSemanticFusion（全局语义）**：接收 SigLIP2 对前/后视图的 pooled embedding（各 768 维），通过以下流程融合到 bottleneck 特征中：
   - 对每个视图的 768 维 embedding 做 LayerNorm + Linear 投影到 128 维（GELU 激活）；
   - 为每个视图添加可学习的 view embedding（128 维）；
   - 经 1 层 TransformerEncoderLayer（`d_model=128, nhead=4, dim_feedforward=512, batch_first=True, norm_first=True`）做跨视图注意力；
   - 对序列做 mean pooling 得到全局摘要，与各视图 token 拼接为 256 维向量；
   - 通过 FiLM 调制：256 维向量经 LayerNorm + Linear(256→256) + GELU + Linear(256→512) 输出 scale 和 shift 各 256 维，作用于 mid block 输出的 bottleneck 特征图上（`x = x * (1 + scale) + shift`）。
   
   关键的初始化策略：最后的 Linear 层权重和偏置均初始化为零，使得训练开始时 FiLM 调制为零贡献，parser 的初始输出完全由几何监督驱动。语义校正必须在训练过程中从有监督的路由错误中学习，而非在初始化时就干预几何解。

2. **SpatialSemanticFusion（空间语义）**：接收 SigLIP2 对前/后视图的 patch-level spatial features（每张 256×512 视图经 ViT patchify 后得到 14×8 个 patch，每 patch 768 维），通过以下流程融合：
   - LayerNorm 归一化（在通道维）；
   - 1×1 卷积（768→64）投影 + GELU；
   - 1×1 卷积（64→256）输出为 bottleneck 残差，bilinear 上采样到 32×64；
   - 残差直接加到 mid block 输出上。
   
   同样采用零初始化：第二个 1×1 卷积的权重和偏置为零，确保语义空间特征在训练开始时不影响几何解。

**预测头**

Parser 从 32 通道的 feature map 出发，经 `feature_dropout`（`Dropout2d, p=0.10`，训练时启用，推理和预览时自动禁用）后，并行输出以下预测：

| 预测头 | 输出通道 | 含义 |
| :--- | :--- | :--- |
| `foreground` | 1 | 前景 logits（sigmoid 后为前景概率） |
| `layer` | 3 | 路由角色 logits：内层(0)、外层(1)、次级/背向表面(2) |
| `part` | 6 | 身体部件分类（非 `geometry_only` 模式） |
| `face` | 6 | 立方体面分类 |
| `layer_face` | 12 | 层级×面的联合分类 |
| `uv` | 2 | 归一化 UV 坐标回归（sigmoid 到 [0,1]） |
| `uv_x` / `uv_y` | 64 / 64 | UV 坐标的离散分类（每轴 64 类，对应 64×64 图集） |
| `surface` | 可变 | 精确表面槽位分类（含复合面和几何回退面） |
| `route_confidence` | 1 | 当前路由决策正确的概率（sigmoid 后） |

此外，全局语义摘要（`semantic_summary`）通过两个线性头输出部件级属性：
- `outer_presence_logits`（6 类）：每个部件是否存在外层的 logits；
- `outer_coverage`（6 类，sigmoid 后）：每个部件外层的大致覆盖率 [0,1]。

**可学习的固定视角路由先验（route_role_spatial_prior）**

这是一个独立的可学习参数张量，形状为 `[view_classes=2, layer_classes=3, H=32, W=16]`。它编码了在大量训练样本中，前视图和后视图的每个空间区域统计上更可能属于内层、外层还是次级表面。在推理时，该先验按视图索引取出，bilinear 上采样到与 `layer` 输出相同的空间尺寸，直接加到 `layer` logits 上。训练时以 10% 概率随机丢弃（per-sample），logit 值通过 `tanh` 限制在 `[-1.5, 1.5]` 范围内，同时施加 L2 和 total-variation 正则化以保持平滑。这一设计使先验成为软统计偏置——对常见结构（如刘海在头部正面上方、帽沿区域的外层分布）提供温和引导，但对罕见皮肤，图像条件化的 CNN 特征可以覆盖先验。

### 4.2 训练监督与损失函数

训练标签完全由可微 Minecraft 渲染器自动生成。对每张 GT 皮肤，渲染器对每个配置的视图（前/后）渲染 RGBA 图像，同时记录每个屏幕像素的来源信息——部件索引、表面方向、层级（内层/外层/次级）、精确 UV 坐标。不需要任何人工逐像素标注。

损失函数（`DenseUVParserLoss`）由以下分量加权组成：

**（1）前景损失**（λ=1.0）
- BCE with logits，正样本权重按 `pos_weight = neg_count / pos_count` 动态计算，上限 20.0。
- Dice loss：`1 - (2*|pred ∩ target| + 1) / (|pred| + |target| + 1)`。

**（2）路由角色损失**（λ=1.0）
- 平衡交叉熵：按各类别有效像素数的 `1/sqrt(count)` 归一化为权重，内层权重下限 0.75，外层权重上限 0.90（防止稀少的外层主导梯度）。

**（3）外层假阳性损失**（λ=1.0, focal γ=3.0）
```text
L_fp = E[ p_outer^γ * (-log(1 - p_outer)) ]   对 target ≠ outer 的有效像素
```
设计意图：将”内层像素被误判为外层”的代价设置得高于”外层像素被漏判”的代价。在 UV 重建中，一个错误的外层 texel 会永久遮挡正确的内层 texel，而一个遗漏的外层 texel 只会留下透明空缺（可在后续修复）。

**（4）外层假阴性损失**（λ=0.75, focal γ=2.0）
```text
L_fn = E[ (1 - p_outer)^γ * (-log(p_outer)) ]   对 target = outer 的有效像素
```
γ 值低于假阳性损失，体现”宁可漏判，不可误判”的不对称设计原则。

**（5）主路由交换损失**（λ=1.0, focal γ=2.0）
```text
L_swap = 0.5 * (L_inner + L_outer)
L_role = E[ (1 - p_correct)^γ * (-log(p_correct)) ]   分别对 role ∈ {0,1} 的像素计算后取平均
```
这是宏平均（macro-averaged）损失：分别计算内层和外层类别的平均损失，再取二者的均值。与按像素数加权的普通交叉熵不同，宏平均确保少数类（外层）不会因为像素数少而被多数类（内层）的梯度淹没。

**（6）投影 texel 一致性损失**（λ=0.25）
对渲染到同一 GT UV texel 的多个源像素，计算它们路由概率的方差，要求投票一致。分组键为 `(batch_item, GT_role, flat_uv_index)`。仅对包含多个源像素的 texel 计算，避免单个观测的真空损失。

**（7）可见外层候选 alpha 监督与跨视角一致性**（λ=0.50）

逐像素路由标签只能监督最终实际可见的表面，无法直接约束“本来应当透明、却被模型误认为外层”的几何候选。为此，训练会把每个视角的外层候选投影回 64×64 UV 图集，并直接使用 GT 外层 alpha 监督其 `p_outer`：

- GT alpha=1：该外层 texel 确实存在，鼓励模型保留外层；
- GT alpha=0：该位置应当透明，惩罚内层、眼睛、脸部或背景被错误路由为外层。

这里必须区分“单视角可见性监督”和“跨视角一致性”。在当前 `front_left + back_left`、256×512 映射中，每个视角直接看到 607 个外层 texel；两视角并集为 1136 个，占完整 1632 个外层 texel 的 69.6%；两视角交集只有 78 个，占可见并集的 6.9%（占完整外层图集的 4.8%）。因此：

- alpha 监督作用于两个视角的全部 1214 次候选观测，对应 1136 个不重复的可见外层 texel；
- 只有概率 disagreement 项限制在 78 个共同可见 texel 上，要求不同视角对同一外层 texel 给出接近的概率；
- 不再要求一个 texel 必须同时被两个视角看到，正脸、眼睛和后脑等单视角区域也能获得外层正负监督。

为了进一步抑制少量高置信度的 inner→outer 错误，系统会从透明外层候选中选取 `p_outer` 损失最高的 20% 作为 hard negatives，并以 0.75 的内部权重加入该损失。训练日志同时记录单视角并集覆盖率、交集占比、可见负样本数和 hard-negative 数量，避免只观察总 loss 而忽略实际监督覆盖范围。

**（8）路由置信度损失**（λ=0.25）
BCE with logits，target = `(predicted_role == GT_role)`。对次级像素，还额外要求 surface 分类也正确。

**（9）路由先验正则化**（λ=0.001, TV weight=1.0）
`L_prior = ||prior||₂² + 1.0 * TV(prior)`，其中 TV 为空间维度的 total-variation（水平和垂直方向一阶差分的平方均值）。

**（10）辅助损失**
- `part` 交叉熵（λ=0.5）
- `face` 交叉熵（λ=0.5）
- `layer_face` 平衡交叉熵（λ=1.0）
- `uv` smooth L1 回归（λ=0.25）
- `uv_x / uv_y` 离散分类交叉熵（λ=1.0）
- `surface` 平衡交叉熵（λ=1.0）
- `affine` translation / log-scale smooth L1（λ=1.0，仅当启用时）

**可微软 UV 投射与多视图渲染损失**

除上述监督分类损失外，训练还包含一个可微分支：parser 的路由和表面概率被软投射（soft splat）到 64×64 UV 图集上，生成临时的皮肤纹理，再通过可微渲染器渲染回配置的视图。软 UV RGB 误差（λ=0.25）、软 UV alpha 误差（λ=0.35）、内/外层可见 texel 召回率（各 λ=0.50，其中 50% 权重集中在最差 10% 的 texel 上）、多视图渲染 RGB 误差（λ=0.20）和多视图渲染 alpha 误差（λ=0.25）均作为损失项加入训练。错误的路由决策将通过这些可微渲染损失同时接收颜色和轮廓梯度，为分类监督提供补充信号。

所有软 UV 和渲染损失项的 λ 均可设为 0，此时训练退化为纯分类监督。推理阶段始终使用硬路由（argmax + 网格取色，详见第五节），不涉及任何软投射或可微渲染。

### 4.4 推理路由与门控

推理时，parser 的软概率输出经过多层门控才转化为最终的硬路由决策：

1. **投影 texel 共识与非对称 outer 准入**：每个源像素的路由概率按中心加权方式投票到其投影的 UV texel 上。最终每 texel 的概率为局部像素概率（40%）与 texel 级聚合得分（60%）的软加权混合。所有普通 outer 决策必须同时通过本地 outer 证据（置信度 ≥0.80、margin ≥0.35）和 fused texel 证据（置信度 ≥0.80、margin ≥0.35）；高置信 raw outer 不再拥有绕过共识的通道。若 fused inner 明确胜出，候选会被改为 inner；若 outer 仍领先但没有达到准入门槛，则保留它的 outer UV 身份但将观测标记为未知，不把不确定颜色错误写入 inner 或 outer 图集。日志分别通过 `consensus_outer_to_inner_pixels`、`consensus_outer_gate_rejected_pixels` 和 `consensus_outer_gate_deferred_pixels` 记录这三类结果。

2. **跨视角外层可见性检查**：对于 78 个共同可见的外层 texel，如果一个视角高置信支持外层，而另一个视角在同一 texel 上明确看到背景或高置信内层，则形成冲突并否决该外层候选。这项规则只处理确有共同可见证据的位置，不会拿后视图去强行裁决仅在正面可见的眼睛或衣服图案。

3. **保守外层门控**（默认 `conservative` profile）：
   - 外层置信度 ≥ 0.80，内外层 margin ≥ 0.55；
   - 外层几何覆盖（footprint coverage）≥ 0.25；
   - 每外层 texel 最少 15 个有效源像素；
   - 背景色边缘像素（与检测到的背景色差 ≤ 8/255）被排除。

4. **几何救援**：当某个 texel 的源像素位于外层独有的轮廓区域（`outer_mask > 0` 且 `inner_mask == 0`），或路由到精确的次级/背向面槽位时，门控放宽至置信度 ≥ 0.60，margin ≥ 0.25，覆盖 ≥ 0.10。精确几何证据可以救回被 outer 准入门槛暂缓的观测。

5. **语义救援**：parser 预测的部件级 `outer_presence` 和 `outer_coverage` 较高时，可以放宽已经通过 texel 准入的外层观测的后续置信度与覆盖率门控；这种宽泛的部件级语义不能绕过 fused texel gate，避免“头部存在帽子或头发”被错误解释为眼睛、脸部所有像素都应属于外层。

默认配置为 precision-first：`保守 profile` 优先保证已输出的外层 texel 是正确的，而非追求尽可能多输出。未通过门控的外层像素在 UV 图集中保持透明——确定性修复不会凭空创建外层 texel。

调试图也明确区分变换前后：`parser_debug_face_raw.png` 和 `parser_debug_layer_face_raw.png` 使用原始输入坐标中的 head logits 与未变换 flood mask，不再被 affine 或后续路由过滤制造出假孔洞；`parser_debug_face.png`、`parser_debug_layer_face.png` 和各类 routed overlay 则反映 canonical 坐标中的最终硬路由。排查时应先比较 raw head 与 `parser_debug_observed_canonical.png`，再检查最终 routed 输出。

## 五、UV 重建

即使部件和层级路由正确，颜色取样仍可能出错。早期方法使用 texel 中心、加权均值或连续 RGB 回归：当投影存在轻微偏移时，中心点可能落在相邻格；当一个网格单元同时含有前景和残余背景时，均值会创造输入图中根本不存在的中间色；生成模型则可能进一步把这些颜色推向高饱和区域。

当前默认的 `grid_mode` 直接在每个拟合网格单元中统计安全来源像素的真实 8-bit RGB，选择出现次数最多的颜色。它具有以下性质：

- 输出颜色一定来自输入图，而不是回归或平均出来的新颜色；
- UV 中心距离只在多个颜色票数相同时用于打破平局；
- 角色内部像素优先于边界像素；
- 与背景色接近的边界残留会被排除；
- 外层 texel 必须获得足够数量的有效来源像素，避免少量背景碎片成为突出的二层皮肤。

这一步体现了新工作流最重要的变化：**对于已经观测到的颜色，系统做的是证据聚合，而不是图像生成。**

路由阈值也不再追求单一的“越高越好”。外层门槛过低会把内层或背景误认为外层；门槛过高又会删除真实的刘海、帽子边缘和腿部二层皮肤。更合理的方法是联合使用分类置信度、内外层 margin、几何覆盖、部件级外层存在概率、来源像素数量和多视图一致性，并分别监控外层 precision 与 recall。

## 六、贪心拓扑修复

Dense UV Parser 的最终产物是一张局部 UV 贴图（输出文件 `parser_pred_uv.png`）：只有能从前后视图中确定路由和颜色的 texel 被写入，其余区域保持透明。那些不可见的内层 texel——例如头顶、脚底、躯干侧面——因此留空。在引入更复杂的生成补全之前，我们增加了一种完全确定性的修复策略，用于快速获得基线结果并暴露 parser 的真实上限。

### 填充顺序：按 Minecraft 拓扑而非 UV 坐标顺序

修复不是简单按 UV 图的 x、y 坐标递增来遍历。相邻的 UV 坐标在三维空间中不一定相邻——例如头部的正面和背面在 UV 图上被头部顶面和底面隔开，但在三维空间中它们紧密相邻。因此，填充顺序按照每个部件的拓扑结构逐面定义：

1. **正面和背面（face 0 和 face 1）**：从边界向中心逐圈填充。最外层一圈先被修复，然后逐圈向内推进。这确保了颜色从已知的区域向未知中心扩散时，遵循纹理的自然连续性。

2. **左侧面和右侧面（face 2 和 face 3）**：从左右两个边界向中间逐行填充。同一行内优先使用同行的已知颜色，再退回到三维最近邻。这避免了手臂或躯干侧面出现从头顶"借"来颜色的荒谬情况。

3. **顶面和底面（face 4 和 face 5）**：同样从边界向中心逐圈填充。

### 修复决策：对称优先，三维最近邻兜底

对每个空缺的内层 texel，算法按以下优先级尝试填补：

1. **对称位置优先**：检查该 texel 的左右镜像位置是否已经定义。Minecraft 皮肤左右两侧高度对称——如果左脸已经确定了颜色，右脸大概率具有相同的颜色。镜像匹配基于三维世界坐标计算，而不是 UV 图的像素坐标。

2. **同部件三维最近邻**：如果对称位置也未知，则在同一个身体部件中寻找三维空间中距离最近的已知 texel。与简单的 UV 图曼哈顿距离不同，三维空间距离能够正确处理跨面邻接——例如头部正面右侧边缘的 texel 在三维空间中紧邻头部右侧面的 texel，而在 UV 图上它们可能相距很远。

3. **行优先策略**：对左侧面和右侧面，优先在同一行内寻找来源。这保持了纹理的水平连续性——一条腰带或袖口应该统一环绕手臂，而不是在不同高度出现断裂。

4. **级联传播**：新填补的内层 texel 可以立即作为同一部件后续位置的来源。这意味着如果手臂正面只有一小块区域已知，它能够逐步向外传播，而不是每个空缺都去同一个来源取色。

5. **硬性不跨部件**：不会为了填满 UV 而从头部向身体、从躯干向手臂等跨部件复制最近颜色。

6. **安全兜底**：如果对称位置以及当前部件都没有任何可靠来源，则继续保持透明。

### 外层保护

修复算法永远不会创建、删除或改写任何外层 texel。已确认的外层 texel 可以作为内层颜色的证据来源（例如手臂外层皮肤的颜色可以传播到同一手臂的内层空缺），但反过来不行——内层颜色永远不会影响外层。

### 确定性修复的价值

该确定性修复算法在代码中对应 `simple_inpainting` 模块（输出文件 `parser_pred_uv_simple_inpainting.png`）。它的价值恰恰在于可解释和可复现：

- 如果 simple inpainting 已经得到不错的渲染结果，说明 parser 的观测覆盖和颜色还原基本正确，问题主要来自不可见区域——这正是拓扑补全需要解决的部分。
- 如果 simple inpainting 把大片区域扩散成单一颜色，说明该部件可用证据太少，需要改进视角覆盖、路由召回或后续生成模型，而不是寄希望于补全模型"猜"出合理结果。
- 如果头部修复正确但手臂出现了跨部件污染，可以追查到拓扑定义本身。

在完整的工作流中，确定性修复结果（`parser_pred_uv_simple_inpainting.png`）和最终输出的 64×64 皮肤文件（`pred_uv.png`）都会保留，方便对比确定性修复与后续生成补全的差异。当前版本中，最终皮肤直接取自确定性修复——还没有接入生成补全模型，因此固定 checkpoint 和运行环境后的推理链路不包含随机生成步骤；这与训练阶段默认采用的快速、非逐位确定 CUDA 模式是两个不同概念。

## 七、当前局限性

新的工作流提高了生成皮肤的质量，但仍有明确边界：

- **依赖规范化视角。** 当前几何映射针对固定前后视图，明显的姿态、透视或缩放变化会降低精度。
- **目前以标准 Steve 手臂为主。** Slim 手臂需要客户端使用简单的工具转换，通常不影响低像素表达。
- **阶段一目前依赖闭源模型。** 这限制了完整链路的可复现性、成本控制和自主迭代能力；当前策略是把它作为数据冷启动与方案验证工具，而不是最终架构。
- **阶段一错误会继续传递。** 背面幻觉、缺失配饰和错误人物比例无法通过 UV 逆投影自动恢复。
- **同色相邻结构仍有语义歧义。** 无光照渲染中，脸、下巴和脖子可能没有接缝，需要几何位置、固定视角先验与全局语义共同判断。
- **外层路由仍是最困难的分类。** 外层几何只比内层略大，少量边界偏移就可能造成内外层互换；透明外层还会暴露更深表面。当前方案仍然存在内外层皮肤路由错误、不对称等问题。
- **真正不可见的纹理没有唯一答案。** 确定性修复只能传播同一部件中已有的颜色，不能恢复参考图里从未显示的图案。

## 八、总结

本文介绍了一条两阶段的 Minecraft 皮肤生成工作流：第一阶段将任意角色参考图转换为规范化的前后渲染视图；第二阶段通过几何拟合、语义路由、网格取色和确定性拓扑修复，从渲染图中重建 64×64 RGBA UV 贴图。

第二阶段的设计遵循一个明确的优先级：能用几何确定的步骤不引入模型，能从输入直接取色的步骤不引入生成。具体而言：

- 前景提取使用确定性泛洪，不对模型输出做概率阈值；
- 像素到 UV 的映射由预计算几何投影提供，不使用姿态估计或可变形对齐；
- 内层/外层/次级表面的路由由 Dense UV Parser 以监督学习解决，训练标签由渲染器自动生成；
- 可见 texel 的颜色直接从输入图的投影网格中统计众数，不使用回归或生成；
- 不可见的内层 texel 由拓扑感知的确定性规则在同部件内传播，不创造新颜色、不跨部件复制。

这套方案的收益体现在三个层面：可见区域的颜色可追溯到输入图中的具体像素，具备完整证据链；每个处理步骤的错误模式可独立评估和定位；几何、语义和修复模块可以各自独立升级或替换，不影响其余环节。

当前方案的主要局限在于第一阶段依赖闭源图像模型，且第二阶段尚未接入生成式补全模块来处理真正不可见的纹理区域。后续工作将围绕两个方向推进：持续积累”原图—规范化渲染—UV 皮肤”三元组数据，训练不依赖闭源模型的阶段一；在 parser 证据质量达到要求后，引入以拓扑约束和 parser 置信度为条件的生成补全，补齐不可见区域。
