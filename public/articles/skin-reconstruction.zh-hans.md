# 图生皮肤的新路径：从规范化渲染到 Minecraft UV 重建

**作者：EntropyDrop Dev Team**
**首发：2026-07-25**

**更新：2026-09-08 · SkingToolkit v104**


> 本文依据 SkingToolkit `v104` 分支提交 [`43e676d`](https://github.com/EntropyDrop/SkingToolkit/commit/43e676d8231fd3417d86721edb4ef4cef3dda40d) 更新。v104 为已复核、有已知局限的候选，并未替换全局默认模型。

## 前言

在上一篇文章《[从参考图到 Minecraft 皮肤：生成模型训练实践](/public/blog/skingen)》中，我们介绍了一条以图生图模型为核心的技术路线：先把参考图转换为包含 UV 贴图和多视角渲染图的复合目标图像，再通过后处理提取 64×64 皮肤。这条路线证明了大模型能够学习角色特征、像素风格与 Minecraft 皮肤之间的映射，但也遇到了明显的瓶颈。

模型往往只学到了视觉上的近似关系，并没有真正理解衣服上的火箭、小熊、文字或徽章等图形。面对这些细节，它更容易把高分辨率图案直接缩小，得到类似普通降采样的结果：细节逐渐消失，颜色相互混合，关键轮廓的边缘也变得模糊。真正理想的低像素表达，应当先理解图形的含义和最具辨识度的结构，再在有限的像素空间中重新组织这些信息，而不是简单地压缩原图。

为了暂时跨过这个瓶颈，并继续验证后续的 UV 还原方案，我们很不情愿地引入了闭源图像模型作为辅助，将图生皮肤拆分为两个阶段：第一阶段把任意角色图片转换为结构固定的 Minecraft 前后渲染图；第二阶段再从渲染图中逆向还原皮肤 UV 贴图。闭源模型并不是我们希望长期依赖的最终方案。现阶段的重要目标之一，是持续收集经过筛选和验证的“原始角色图—规范化渲染图—UV 皮肤”数据，以便进一步训练一个完全不依赖闭源模型的图生皮肤模型。

当前链路为：规范化前后视图 → 学习式前景提取 → 固定视角几何与语义路由 → 初始 UV 与内层补全 → 最终头部 UV 解码 → 材质重拟合 → 64×64 RGBA 皮肤。

## 相关工作与方案演进

据我们目前能够追溯到的公开资料，这条思路较早由网友 DDJ 提出。2025 年底，他演示了使用 Banana 图像模型辅助生成 Minecraft 皮肤的方法；2026 年 2 月，又在此基础上训练了专用模型，以改进从生成图中提取 UV 贴图的效果，并随后公开了模型。相关资料包括：

- [2025 年 11 月 23 日发布的方案演示](https://www.bilibili.com/video/BV1NqUNBVEu5)
- [2026 年 2 月 16 日发布的 UV 提取改进](https://www.bilibili.com/video/BV1muZTBkE53)
- [开源模型 MCSkin](https://huggingface.co/d1ngdongji/MCSkin)

2026 年 3 月，另一组研究者提出了相近的两阶段路线，并在论文 [BLOCK: An Open-Source Bi-Stage MLLM Character-to-Skin Pipeline for Minecraft](https://arxiv.org/abs/2603.03964) 中进行了更系统的研究。

在这些工作的基础上，我们主要沿两个方向继续改进：

1. 提高 Banana 模型输出的稳定性，减少相机视角、人物姿态、缩放比例和画面位置的偏差，使内层与外层皮肤尽可能落在预定的投影网格中。
2. 重新设计 UV 还原流程，从规范化渲染图中直接重建带透明通道的 64×64 UV 贴图。

## 零、前置基础：渲染器、几何与训练标签

### 0.1 项目关系与渲染职责

`differentiable_minecraft_renderer` 与 `mc_skin_utils` 提供 Minecraft 网格和相机配置；SkingToolkit 加载预计算映射，执行可微渲染、几何查表与 UV 重建。Steve 模型由 6 个部件、每部件 6 个面、内外 2 层组成，共 72 个矩形面。

离线的 `generate_mappings.py` 为每个固定视角生成像素到 UV 的候选映射。主要数据包括：

| 映射 | 含义 |
| :--- | :--- |
| `inner_uv_map` / `inner_mask` | 内层候选 UV 坐标与投影覆盖 |
| `outer_uv_map` / `outer_mask` | 外层候选 UV 坐标与投影覆盖 |
| `outer_uv_layers` / `outer_masks` | 深度排序的外层候选 |
| `composite_uv_layers` | 内外层合成后的候选，并记录层级身份 |
| `geometry_uv_layers` / `geometry_masks` | 全部矩形面的几何候选，供精确表面路由使用 |

`SkingToolkit/renderer.py` 中的 `DifferentiableRenderer` 加载这些 grid 和 mask，通过 `F.grid_sample` 从 64×64 皮肤采样，再按深度与 alpha 合成。训练时，它从已知 UV 生成渲染图和监督标签；推理时，它提供候选几何，并在头部材质拟合阶段重新渲染最终 UV，计算与输入图的颜色误差。

### 0.2 几何为什么不能单独决定 UV

同一个屏幕像素可能对应直接可见的内层、覆盖其上的外层，或透过外层孔洞看到的次级表面。几何能列出这些候选，却不能仅凭位置判定当前颜色属于哪一层。同色的脸、胡子和耳机边缘尤其容易混淆。

因此，渲染器回答“像素可能来自哪里”，parser 回答“根据图像证据，更可能来自哪里”。对于合成数据，已知的 GT 皮肤让渲染器可以直接提供前景、部件、面、内外层、次级表面和 UV 坐标标签；对于真实生成图，这些归属仍需模型判断。

### 0.3 固定视图与语义特征

v104 保持有序的 `front_left`、`back_left` 双视图输入。模板采用正交投影、固定缩放与轻微行走姿态。输入拼图按宽度分成左右两幅，再分别缩放到对应映射的尺寸；原始拼图尺寸与单视图张量尺寸是两个概念。视图顺序、相机和映射必须与 checkpoint 配套，不能任意替换。

基础 Dense UV Parser 使用冻结的 SigLIP2（`google/siglip2-base-patch16-224`）提取视觉语义。`MultiViewSemanticFusion` 将前后视图的全局特征融合到 U-Net，`SpatialSemanticFusion` 提供局部 patch 特征。基础训练可将这些特征预计算为 FP16 mmap 缓存，减少重复前向计算。v104 的续训则主要使用冻结父流程产生的自动 UV 与图像证据缓存，只更新最终头部解码器。

### 0.4 自动标签与真实局部标注

标准训练输入为 64×64 RGBA 皮肤；Slim/Alex 皮肤可通过 `alice_to_steve()` 归一化到 Steve 布局。普通原生皮肤提供真实颜色和 alpha，程序化构造的头发、胡子、帽子、眼镜与耳机还提供明确的语义和材质关系标签。

自动渲染仍是主要监督来源，但到 v104，训练也包含三个已有真实身份的局部标注。只有已确认区域作为明确目标，其余区域使用经过复核的旧模型输出进行一致性训练。没有标注的原生纹理保持语义未知，不能凭颜色猜测类别，也不能把教师输出称作人工真值。具体数据隔离与验证范围见第七节。

## 一、阶段一：把任意参考图变成规范化前后视图

第一阶段采用多图参考。图 1 是待转换的角色原图；图 2、图 3 和图 4 则使用不同皮肤，但保持完全相同的画布布局、相机方向、人物姿态和模型比例。多张模板并不是为了向模型提供更多角色内容，而是反复强调输出必须遵循的几何约束，并共同限定 Minecraft 的低像素视觉风格。这样可以降低模型照搬某一张模板外观的概率，同时减少视角漂移、比例变化和肢体错位。

Prompt 的设计也围绕这两个目标展开：首先锁定 Minecraft 双图层玩家模型及其贴图分辨率；其次锁定相机、姿态和画面布局；最后才要求模型在这些约束内还原角色特征。当前使用的 Prompt 修改自 DDJ 推荐的版本，具体如下：

```text
生成 [图 1] 中角色的 Minecraft 形象。

- 人物模型必须与 Minecraft 玩家模型相同，并采用包含内层和外层贴图的双图层结构，不能添加额外的几何元素。贴图分辨率不得高于 Minecraft 支持的分辨率，参考 [图 2]、[图 3] 和 [图 4]。

- 生成角色的尺寸、朝向、姿势、相机视角和画面位置必须与 [图 2]、[图 3] 和 [图 4] 完全一致。

- 使用容易区分前景的纯色背景。

- 在满足上述约束的前提下，尽可能准确地还原 [图 1] 中角色的外貌特征、全身服装和饰品，但不要生成手持物品或披风。
```

测试中我们发现，图像生成模型很难稳定遵循 Prompt 中的精确数值。直接指定 yaw、pitch、FOV 或角色像素尺寸，不仅不能保证几何一致，有时反而会增加输出波动。相比抽象的描述，模型更擅长从参考图中模仿相机方向、构图比例和人物姿态。因此，这一阶段的重点应当放在参考模板的设计上。

模板也并非越复杂越好，比如在模版中增加单独的内外层皮肤渲染或者增加网格辅助，Banana模型无法输出正确的图像。经过多轮测试，我们最终得到了一组稳定性较高的渲染模板，其共同特征如下：

- 使用正交投影，不添加光照，避免透视缩放和明暗变化干扰后续取色；
- 采用 1:1 正方形画布，左半部分放置角色正视图，右半部分放置角色后视图，并使用随机纯色背景；
- 角色采用小幅度摆动手脚的行走姿态，使四肢与躯干适当分离，同时避免姿态变化过大；
- 前后视图覆盖主要可见表面，但头底面等区域仍缺少投影证据，透明外层和遮挡也会减少实际观测。

## 二、前景提取：分开处理轮廓与取色

早期版本从左上角背景种子执行 flood fill。它适合干净的纯色背景，但封闭孔洞、近似背景色的衣物和细帽沿会暴露局限。v104 配套流程使用经过 Minecraft 渲染数据微调的独立 BiRefNet 去背景模型；冻结预训练 backbone，仅训练 decoder。该模型与 UV parser 分开固定版本。

去背景训练使用 4096 个训练、128 个验证和 128 个测试皮肤身份，以归一化 RGBA 内容哈希隔离。合成背景包含接近前景的颜色、渐变、噪声和棋盘格，也加入 JPEG 与触边裁剪。模型先按验证集选择，再在保留测试集上评估。

推理保留两种不同用途的掩码：

| 用途 | 条件 | 原因 |
| :--- | :--- | :--- |
| 角色轮廓 | 前景概率 ≥ 0.50 | 保留细帽沿、发尖和配饰几何 |
| UV 颜色来源 | 前景概率 ≥ 0.98，并在 parser 分辨率下内缩 1 像素 | 避免把混合了背景的边缘 RGB 写入皮肤 |

严格取色掩码不会直接删除细结构的轮廓。它排除不可靠的颜色来源，并不保证每个边界像素已经完成物理意义上的前景颜色分离。通用代码仍保留 flood fill 路径，但它不能代表 v104 配套候选的完整流程。

## 三、几何拟合：固定候选与坐标对齐

在已知相机、Steve 几何和前后视图顺序下，系统查找每个像素可能对应的部件、立方体面、层级和 UV。这里不需要从任意姿态重新估计人体骨架，但仍需处理模板输出相对标准投影的位置与尺度偏差。

原图 RGB、预测 logits 与前景掩码必须一致地进入 canonical 坐标。掩码变换使用覆盖信息保留细轮廓，后续取色仍受高置信前景与源像素数量约束；不能为了拒绝背景而在坐标变换时先抹掉真实帽沿。额外 affine refinement 是否启用由配套 pipeline 决定，固定几何并不等于整条推理链没有学习或优化。

几何候选还区分直接内层、直接外层与次级/背向表面。透明外层让某些像素来自更深的面，强行归入最近的内层会把胡子边缘或帽子背面写错位置。几何先缩小候选范围，语义模型再做选择。

## 四、从基础路由到最终头部 UV 解码

### 4.1 基础 Dense UV Parser

`DenseUVParserNet` 的主体仍是带跳跃连接的 U-Net：RGB 与视图 one-hot 拼接后进入 32 → 64 → 128 → 256 通道编码器，再上采样恢复密集特征。冻结 SigLIP2 的全局与空间语义提供上下文，可学习的固定视角先验给路由 logits 添加软偏置。

基础预测包括前景、部件、立方体面、内层/外层/次级表面、UV 坐标、精确表面槽位和路由置信度。训练结合分类、UV 回归、错误外层惩罚、投影 texel 一致性，以及可微软 UV 与多视图渲染损失。推理通过几何候选、路由置信度、覆盖率和源像素证据得到初始 UV。

早期实验还包含投影外层 occupancy、连通组件救援等可选模块。这些开关不能仅根据类名或通用脚本默认值来判断是否启用；复现某个版本必须读取对应 pipeline。v104 新增的头部拓扑模块位于最终解码器中，与基础 parser 的可选 occupancy 分支不是同一个模块。

### 4.2 联合头部语义：脸、头发和配饰共同判断

从 v102 开始，头部使用同一个 14 类分布表示弃权/未知、脸部、内外层头发、内外层胡子、眼镜、耳机、内外层帽身/帽带、帽沿与皇冠。前后头部特征通过联合注意力交互，同一人物的两个视图共同提供证据。

这解决的是独立分类器可能同时认为“这里是脸”和“这里是皇冠”的结构性矛盾。v103 修订进一步让最终 UV 的语义与外层占用来自同一类别分布：对于外层查询，内层类别概率计入“没有外层”的证据，不能因为检测到了内层头发，就认为该格应新增外层。

最新候选还保留两项经过回归检查的调整：关闭曾经误删头发的整头几何清理（`joint_head_geometry_mode=disabled`）；将学习式面重分配限定于胡子（`head_surface_routing_scope=beard`），让头发保留原几何路由。帽子、皇冠、耳机仍有各自的语义与材质处理。

### 4.3 FinalHeadUVDecoder：直接监督最终输出

只提高屏幕像素分类准确率，并不能保证最终 UV 没有缺块、错层或颜色污染。`FinalHeadUVDecoder` 因此直接读取自动 UV 和前后视图证据，对 768 个合法头部 UV 格子（6 面 × 8×8 × 2 层）建模。

每格查询包含当前 RGBA、对应镜像格与跨层格、立方体坐标、面与层身份。候选投影把两幅头部图中的局部 RGB、前景、语义和所属面概率送入该格，即使外层格当前为空，也有机会读取它的潜在图像证据。注意力提供整头上下文，局部邻域输入缓解生成图的小幅错位。

解码器学习三个相互关联的决定：

1. **保留还是修改**：对每格建立明确的编辑决定，修正遗漏与误加，同时惩罚改坏原本正确的格子。
2. **占用与颜色**：直接监督最终外层 alpha、颜色修改开关和 RGB 修正；身体、无效 UV 与内层 alpha 在结构上保留。
3. **材质是否对应**：学习左右镜像及内外层对应位置是否应共享颜色，只在预测连接的组内统一 RGB，允许不对称、部分连接和真实孔洞。

推理读取图像与自动 UV，不读取训练标注、身份或文件名来查表修正。该学习分支可以修改头部外层，因此旧文“所有外层只能保持 parser 初始取样结果”的描述已不适用于最终输出。

### 4.4 v104：学习真正的跨面邻域

v104 在最终解码器加入 `HeadTopologyContext`。它分别聚合同一立方体面内的邻居和真实接缝另一侧的邻居，再将这两类上下文与原特征一起送入可学习残差模块。它不会把 PNG 图集中碰巧相邻、实际并不相接的 UV 小岛连起来。

新增模块的最后一层零初始化，加载修订 v103 权重时预测逐位一致，之后才通过训练学习跨面关系。监督包含两部分：

- **真实边界损失**：用 GT alpha 标记相邻格应当连续还是断开，同时学习完整帽沿与真实开口，不把所有相邻格强制设成相同。
- **连通区域扰动**：沿真实立方体邻域制造整块缺失或多余外层，让模型学习修复跨面错误，而不只是零散像素噪声。

v104 同时增加 `mask_unknown_relations`：没有语义标注且颜色不冲突的材质关系不作为负例；双方可见且目标颜色不同仍是明确负例，正例则需要语义标注支持。这样既不会把未知关系误教成“不相连”，也不会仅因同色就强制连接胡子。

## 五、颜色恢复：网格取样与最终材质拟合

初始 UV 仍采用 `grid_mode`：在安全的投影源像素中统计实际 8-bit RGB，选择支持最多的颜色，UV 中心距离仅用于打破同票。它避免直接平均前景与背景形成原图不存在的中间色。

但最终头部几何发生改变后，原来的可见性也会改变。例如删掉错误外层头发后，下面原本被遮住的内层颜色会露出来。如果沿用编辑前的颜色，即使 alpha 正确，额头也可能出现杂色。

v104 的配套配置因此在全部学习式几何编辑完成后，执行 64 步最终头部材质拟合：

1. 根据最终 alpha 重新计算两视图可见性，从高置信源像素拟合头部 RGB。
2. 使用学习到的颜色归属和边界排除信息，并启用 `final_head_material_protect_inner_footprints=True`。把配饰冲突投影回整个内层 UV 格子的取样范围，避免只排除少量已分类的耳机像素后，剩余绿色仍污染内层头发。
3. 恢复模型预测的镜像与跨层材质连接；只有共享颜色后的源图重建误差严格下降，才接受拟合结果。

该步骤保持 alpha 和身体不变；没有可信头部源像素或误差未下降时保留原色。最终 RGB 可能经过学习修正与优化，不能再声称每个输出颜色都逐字节来自输入众数。这仍是有图像证据约束的重建流程，尚未接入针对任意不可见纹理的通用生成补全模型。

## 六、确定性内层补全在完整流程中的位置

`simple_inpainting` 仍为初始部分 UV 提供可解释的内层补全。它按部件与立方体拓扑工作：正背面从边界向中心逐圈填充，侧面按行向中间推进，顶底面再由边缘向内填充。

缺失格优先寻找同部件镜像来源，再使用同部件三维邻近颜色；侧面优先同行，新填格可以继续传播。没有同部件证据则保持透明，不从头部向躯干等跨部件复制。镜像只是此阶段的补全启发式，不能证明真实纹理一定对称。

这个模块本身不创建、删除或修改外层格。已确认的同部件外层颜色可以作为内层来源，但其输出只是中间结果。完整候选随后还有隐藏头部材质处理、学习式最终头部 UV 修正和最终 RGB 拟合，所以最终皮肤不再等同于单独运行 `simple_inpainting` 的产物。

调试时应分别比较初始观测 UV、内层补全结果、最终头部 alpha 和最终材质。渲染图看起来连续不代表 UV 每格正确；同样，UV 格子总数增加也不能证明头发恢复，因为增加的格子可能位于错误的面。

## 七、v104 的训练、选择与实际结果

### 7.1 训练范围与身份隔离

v104 以经过复核的修订 v103 为起点，冻结父模型，仅训练最终头部解码器。新增 448 个训练源身份，其中 384 个保留原生纹理，64 个用于同人无配饰/眼镜/耳机配对；另新增 80 个验证和 80 个测试身份。配对图只改变配饰，脸、头发和胡子保持一致。

最终合成缓存如下；“图像”指一份双视图样本，不等于独立身份数：

| 集合 | 合成图像数 | 归一化 UV 源身份数 |
| :--- | ---: | ---: |
| 训练 | 1120 | 928 |
| 验证 | 248 | 200 |
| 测试 | 112 | 80 |

三个集合按归一化 RGBA 内容去重并互不重叠。隔离范围是本次解码器训练，不能据此声称这些身份从未进入冻结父模型的历史训练。旧缓存作为父流程错误扰动回放；新增数据使用当前冻结父流程，半数新增训练身份加入不改变几何的光照、模糊和颜色扰动。

三个已有局部标注真实身份另行采样。两张最新眼部/头发反馈图不参与梯度训练，但参与开发判断；其余真实开发图同样不能被称为独立盲测。

### 7.2 训练配置与 checkpoint 选择

| 项目 | v104 配置 |
| :--- | :--- |
| 优化器 / 初始学习率 | AdamW / 8e-5 |
| 训练长度 / batch | 6000 步 / 8 |
| 训练参数 | 仅最终头部解码器，父模型全部冻结 |
| 原生纹理采样比例参数 | 0.7 |
| 配对与真实局部标注 | 每 4 步一组同人配饰对照；每 2 步最多一个已有真实训练身份 |
| 逐格误改风险权重 | 5，按全部外层格子统一归一化 |
| 边界损失权重 | 0.5 |
| 选中 checkpoint | 第 5000 步 |

验证先区分有候选投影覆盖与无覆盖区域：错误权重分别为 1 和 0.2，旧缓存回放再乘 0.25。原因是头底面在这两个视图中缺乏证据，不能让它掩盖可见头发与眼部的变化；该加权仅用于评估与选择，并不是推理填充规则。

第 200 步没有通过已有胡子检查，被排除。合格候选中，第 5000 步验证加权错误最低，从 1881.25 降至 1722.80，下降 8.42%，因此没有直接采用最新的第 6000 步。

### 7.3 保留测试集：可见改善与底面退步

完成验证选择与真实图片视觉复核后，才打开训练前锁定的 112 张合成测试图：64 张原生皮肤，以及 16 个身份各自的无配饰、眼镜、耳机三图。测试之后没有重新选择权重。下表衡量最终头部外层几何，比较对象为**已修订 v103**：

| 测试区域 | v103 IoU | v104 IoU | 误加格数 v103 → v104 | 漏检格数 v103 → v104 |
| :--- | ---: | ---: | ---: | ---: |
| 原生皮肤，有视图覆盖 | 86.63% | 87.62% | 370 → 337 | 481 → 447 |
| 原生皮肤，无视图覆盖的头底面 | 43.94% | 37.56% | 71 → 90 | 396 → 442 |
| 原生皮肤，全头部 | 81.69% | 81.69% | 441 → 427 | 877 → 889 |
| 配饰配对，全头部 | 97.49% | 97.75% | 72 → 70 | 34 → 25 |
| 配饰配对，有视图覆盖 | 97.31% | 97.44% | 66 → 70 | 34 → 25 |

原生皮肤可见区域总错误减少 7.87%，但全头部 IoU 精确值为 0.816944 → 0.816866，基本持平且略降；配饰可见区域误加还增加了 4 格。头底面明显退步，不能说所有指标都改善。

这些是身份隔离的合成渲染测试，不是具有人工逐格真值的真实生成图准确率。测试使用相同冻结父流程缓存衡量最终 alpha，最后的颜色拟合不会改变 alpha，因此也不能把这张表当作 RGB 质量评分。

### 7.4 真实图片检查与候选状态

完整流程重跑了 43 张原图：3 张训练拟合检查和 40 张无梯度真实开发图。复核包含前后渲染、原始头部 UV 和外层 alpha 差异：

- 耳机/麦克风反馈例的指定眼周区域误加保持 0。
- 头发反馈例相对 v101 的 96 格历史参考，保留格数从 77 增至 85，参考外格数仍为 0；该历史输出不是人工真值。
- 既有胡子、鼻子、皇冠、耳机颜色污染、眼镜额头与四面帽沿等指定检查通过。
- 全部 43 张身体与修订 v103 逐字节一致。19 张重复完整推理的 alpha 与身体一致；17 张可见 RGB 一致，2 张最大通道差为 1/255。

视觉复核仍看到复杂发型的侧后面/顶面零散格和模糊的帽子文字。部分新增头底面外层格没有输入视图证据支持，不能从正背渲染确认其正确性。

因此，模型记录为 `reviewed_candidate_with_known_limitations`。截至本文所依据的提交，它没有替换全局默认模型。候选需要同时固定 `parser.pt`、配套 `pipeline.json` 与去背景模型；仅替换 parser 权重不能复现最终颜色保护等行为。

上述配置、选择过程和完整结果见 [v104 训练与复核记录](https://github.com/EntropyDrop/SkingToolkit/blob/43e676d8231fd3417d86721edb4ef4cef3dda40d/dense_uv_parser/V104_TRAINING.md)。

## 八、批量导出与结果可追溯性

v104 分支新增 `run_all_edited_v104.py`，递归处理 `*_edited.png`，输出同目录的 `*_result_v104.png`（64×64 RGBA）。它固定使用已复核的第 5000 步候选与配套流程，默认两个 worker。

每个任务保存代码、模型、配置、输入清单与哈希快照；已有 v104 结果先备份再原子替换，原输入与其他版本结果保留。中断后可恢复同一任务，重新核对已完成输出并跳过通过校验的结果，而不是随着工作区代码变化混用版本。

`progress.json` 记录进度，`results.jsonl` 记录逐图来源与输出校验值，`final_audit.json` 记录结束时的保护与格式审计。批量工具可用，不等于所有图片已经运行完毕或通过语义验收；文件来源正确也不能证明每格头发、胡子和配饰正确。操作说明见 [v104 批量导出文档](https://github.com/EntropyDrop/SkingToolkit/blob/43e676d8231fd3417d86721edb4ef4cef3dda40d/dense_uv_parser/regression/v104_batch/README.md)。

## 九、当前局限与后续方向

- **视角依赖。** 固定投影无法补救明显的姿态、透视或比例变化，当前仍以 Steve 布局为主。
- **阶段一依赖闭源模型。** 背面幻觉、缺失配饰和错误人物比例会继续传递到重建阶段；收集“原图—规范化渲染—UV”数据仍是摆脱该依赖的重要路径。
- **未观察区域缺少约束。** v104 的头底面退步说明，跨面上下文并不能替代真实视图证据。需要增加有效视图，或单独研究缺乏证据时更保守的外层预测。
- **真实语义泛化尚未解决。** 复杂发型、遮挡和罕见配饰仍需更广的真实 UV 标注；三个训练身份的局部改善与反复使用的开发图不能代替新测试。
- **颜色和结构要分别验收。** alpha 正确不保证材质正确，渲染自然也不保证 UV 面向与层级正确。最后颜色拟合改善的是源图重建误差，不是真实纹理的完整证明。

两阶段路线保持不变，但第二阶段已从“硬路由、取色、内层补全”发展为几何候选、学习式前景、联合头部语义、最终 UV 解码与可见材质拟合的组合。v104 的实际进展是可见头部的有限改善；下一步需要补充复杂发型与配饰真值，并为未覆盖表面建立更有效的观测和评估。
